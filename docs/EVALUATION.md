# 评测协议

## 比较对象

UrbanTraffic-Bench 使用同一数据库和同一批 100 道交通业务问题评价两种分析方式：

1. **Text2SQL**：模型获取结构化题目、数据说明和完整表结构，直接返回一条只读 SQLite 查询。
2. **TransportX Agent**：Agent 围绕题目读取数据资料、执行查询、利用反馈调整分析过程，并交付最终查询与结果。

两种方式的可用信息和执行能力应随结果一并报告。当前论文对比是完整系统级比较，不将正确率差异单独归因于业务知识、工具调用或执行反馈。

## SQL 执行

- 数据库：SQLite。
- 只允许只读查询。
- 每题 SQL 运行时间上限为 180 秒。
- 超时、运行错误和结果截断均不判为正确。
- 模型版本、推理设置、提示词版本、数据库 SHA-256、任务 SHA-256、超时和重试规则必须随结果保存。

## 结果判定

评分不要求参评查询复现唯一参考 SQL。评分器在统一只读数据库中重新执行最终查询，并依据题目契约比较结果：

- 必需字段必须完整，字段别名可按任务规则兼容；
- 默认不要求行顺序相同，但保留重复行语义；
- 整数和文本原则上精确匹配，浮点容差由 `evaluation_policy` 指定；
- `NULL` 与数值 0 不等价，数值与格式化后的文本不等价；
- 固定 Top-K 按题目指定的排序和边界规则判定；
- 缺失、多出或重复次数不符的结果行判为错误。

## 报告指标

主指标为 100 道交通业务任务的正确率，同时报告单方式、多方式和空间关联三类结果。系统比较还应报告：

- 正确率的 95% 置信区间；
- 同一模型、同一题目下两种方式的 McNemar 配对检验及不一致配对数；
- 任务响应时间的中位数、均值和 P95；
- 最终 SQL 的独立执行时间。

并发数、推理档位或运行窗口不一致时，任务级延迟只用于描述当次实验，不用于推断系统吞吐效率。

## 正式结果条件

正式结果需同时满足：

1. 参考 SQL 可执行且参考结果可复现；
2. 题目、计算口径、参考 SQL 和参考结果完成规定的人工审核；
3. 评分器、输入文件和数据库版本已冻结并记录校验值。
