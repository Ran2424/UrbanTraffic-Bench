# 评测协议

## 计分单位

两个赛道分别计算执行正确率：

- `Open-source SQL Accuracy`
- `Shanghai Mobility Accuracy`

不得将 1,696 道开源题和 100 道上海题直接做微平均。需要单一指标时，可以使用：

```text
Overall Macro Score =
0.5 × Open-source SQL Accuracy
+ 0.5 × Shanghai Mobility Accuracy
```

宏平均只能作为辅助指标，报告必须同时给出两个赛道原始结果。

## SQL 运行

- 数据库：SQLite。
- 只允许只读查询。
- 每题 SQL 运行时间上限为 180 秒。
- 超时、运行错误和结果截断均不判为正确。
- 评测配置、提示词版本、数据库 SHA256 和任务 SHA256 必须随结果保存。

## 结果比较

基础比较规则包括：

- 按题目要求投影必要字段；字段别名可以兼容。
- 默认不要求行序相同，但保留重复行语义。
- 数值容差由任务的 `evaluation_policy` 指定。
- `NULL` 与数值 0 不等价。
- 固定 TopK 允许边界同值对象替换；明确要求保留并列时保留全部并列。
- 大结果任务必须声明 `result_mode` 和可复现的校核方式。

## 提示词

两个赛道共用输出约定：仅返回一条 `<sql>...</sql>` 包裹的只读 SQLite 查询。

开源赛道按数据库提供 schema，可选使用 evidence 和数据库知识。上海赛道按题目组提供固定资料包，并在条件说明中给出日期、空间边界或文本枚举等必要条件。

## 正式结果

自动执行通过不等于标准答案已经完成审定。正式结果应同时满足：

1. 标准 SQL 可执行且结果可复现。
2. 题目、SQL 和结果经过规定的人工审核。
3. 评测器版本和输入文件校验值已冻结。
